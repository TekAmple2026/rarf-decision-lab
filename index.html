Simulation settings

Generates fake incidents (real attacks and harmless look-alikes) and runs each response policy on exactly the same incidents.

  • C1 Manual: every alert joins one analyst's queue.
  • C2 Full automation: if p ≥ 0.5, run the most effective action at once, no rules.
  • C3 RARF: the full framework.
  • C4 ablations: RARF with one part switched off.
Action values come from the thesis's Appendix H catalogue. Everything else (attack mix, timings, detector) is synthetic and illustrative.

What this is

A working demo of the Risk-Aware Response Framework (RARF) proposed in the master's thesis Ethical Decision-Making in Autonomous Cyber Defense: Developing a Risk-Aware Response Framework (University of Lagos). It implements the decision rule from Section 3.14 and Appendix C, and a simplified version of the simulation experiment in Section 3.5.

The decision rule

p_adj = max(0, p − δ) F′(a) = F(a) × [1 + λ × (1 − r(a))] EB(a) = p_adj × e(a) × H − (1 − p_adj) × F′(a) − K(a)

Actions that break a hard constraint are removed first. The remaining action with the highest EB is chosen. If none has EB above zero, the system observes and alerts.

Hard constraints

    What the demo leaves out

    • No real virtual network or trained detector: the simulation uses synthetic incidents and a simulated detector.
    • Harm values are the thesis's illustrative numbers, not values agreed in practitioner workshops.
    • No expert panel or tabletop evaluation.
    • Rate limits and anomaly checks on automated actions are not modelled; the harm budget is.
